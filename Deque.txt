deque

- stack : 최상단에서 삭제와 삽입이 일어남. 반대쪽에서는 불가능함. LIFO
- queue : 한 쪽에서 삽입, 반대쪽에서는 삭제가 일어남. 삽입하는 쪽에서 삭제 불가능 FIFO

덱의 장점
- 개개의 원소들을 각자의 인덱스로 접근할 수 있음.
- 원소를 어떠한 방향으로도 참조해 나갈 수 (iterate) 있음.
- 덱 끝과 시작 부분에 효율적으로 원소 삽입/삭제가 가능함.

덱 vs 벡터
- 벡터와는 다르게, 덱은 양쪽 끝 모두에서 효율적인 추가와 삭제가 가능함.
- 벡터와는 다르게, 덱은 모든 원소가 메모리 상에 연속적으로 존재한다고 보장할 수 없음. 
- 벡터의 경우 capacity가 꽉 찼을 경우 새롭게 한 덩어리의 메모리를 할당하지만
  덱의 경우 메모리 상에서 잘게 쪼개어서 보관함.
- 벡터보다 메모리 공간을 효율적으로 사용하고, 메모리 재할당을 하지 않기 때문에 좀 더 빠름.

template <class T, class Allocator = allocator<T> >
class deque;

T : 보관하려는 타입
Allocator : 어떤 방식으로 메모리를 할당할지, 할당자 타입 / 기본적으로 Heap에 할당함.

멤버 함수
- 생성자
	: 덱을 생성함.
- 소멸자
	: 덱을 소멸함.
- operator=
	: 덱의 내용을 복사함.

반복자
- begin
	: 시작 부분(첫번째 원소)을 가리키는 반복자 리턴
- end
	: 끝 부분(마지막 원소 바로 다음)을 가리키는 반복자 리턴
- rbegin
	: 역순으로 첫번째(마지막 원소)를 가리키는 반복자를 리턴
- rend
	: 역순으로 끝부분(첫 번째 원소 바로 이전)을 가리키는 반복자 리턴
